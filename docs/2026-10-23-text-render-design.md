# 글자 배치·모바일 미리보기·자동 고침 설계

작성: 2026-10-23 · 상태: **검토 중** (승인 전에는 구현하지 않아요)

## 왜 하나
배경 그림만으로는 카드뉴스가 아니에요. agy가 만든 배경 그림 위에 제목과 본문을 **별도 글자**로 올리고(그림 안에 글자를 그리지 않는 원칙, PRD 5절), 휴대폰에서 실제로 읽히는지 보여 줘야 해요. 글자가 잘리거나 그림 속 물건과 겹쳐 안 읽히면 앱이 먼저 고쳐 보고, 그래도 안 되면 사용자가 버튼으로 고쳐요.

## 이번에 하는 것 / 안 하는 것
- **해요:** 글자 렌더링(PNG), 가독성 점검(잘림·크기·대비·겹침), 자동 고침, 직접 조정, 모바일 미리보기, 배경 그림 6장 완성 뒤 검수 단계(`reviewing`)로 넘어가기.
- **안 해요(다음 단계):** 사실·출처 점검, 글로 요청하는 부분 수정(Claude CLI), 최종 승인, PNG·ZIP·출처 기록 내보내기.
- **피해야 할 것:** 점검을 통과하지 못한 카드를 "완료"로 보여 주기, 글자를 고쳤다고 배경 그림을 다시 만들기(agy 사용량 낭비), 고치지 않은 카드의 파일이 바뀌기.

## 사용자가 정한 것
- 카드 모습: 참고 계정(TikTok lu.casteli) 같은 차분한 잡지 화보 느낌, 글자는 휴대폰 기준으로 크게(시안 B: 제목 64px 안팎, 핵심 44px, 본문 32px 이상) — D17.
- 고치는 방식: **자동 고침 + 직접 조정.**
- 렌더러: HTML/CSS + 헤드리스 브라우저(D8), **Playwright + Chromium을 지금 설치.** 글꼴은 Pretendard 공식 GitHub 릴리스(D7).
- **카드에 출처 줄은 넣지 않아요.** 출처는 내보내기 파일(`sources.md`)에만 담아요.

## 카드에 올리는 글자 (AI가 정함)
| 카드 | 맨 위 | 가운데 | 아래 |
|---|---|---|---|
| 표지(cover) | 제목(title) 72px Bold | 핵심 문장(keyLine) 40px | — |
| 본문·요약 | 제목(title) 64px Bold | 핵심 문장(keyLine) 44px SemiBold | 본문(body) 32px Regular |

- 세 덩어리를 한 "글자 상자"에 세로로 쌓고, 상자를 스토리보드의 `imagePlan.textArea`(위·가운데·아래) 자리에 둬요. agy에게 비워 두라고 한 바로 그 자리예요.
- 좌우 여백 88px, 위아래 여백 96px. 가운데 정렬, `word-break: keep-all`, 줄 간격 1.4.
- 생성 이미지 표기: 카드 오른쪽 아래 구석에 작게 "AI 생성 이미지"(20px, 반투명). PRD 5절의 "실제 사진으로 오해할 수 있으면 생성 이미지임을 밝힌다"를 따라요. 정물 사진이 실제 사진처럼 보여서 넣어요. 장식이라 32px 기준에서 빼요.
- 배경 그림(896×1200)은 1080×1350에 `object-fit: cover`로 채워요.

## 렌더링 (D8)
- `cardnews/render/` 새 모듈. 카드 하나 = HTML 한 장(인라인 CSS, Pretendard `@font-face`).
- Playwright Chromium, 뷰포트 1080×1350, `deviceScaleFactor=1`. 글꼴 로딩을 기다린 뒤(`document.fonts.ready`) 점검 → PNG 저장 → 저장한 PNG를 다시 열어 1080×1350인지 확인.
- 파일: `results/cards/card_N.v{cardVersion}.png`. 렌더용 HTML도 옆에 남겨요(`.html`). 고치지 않은 카드의 PNG는 그대로예요.
- 카드 상태: `image_ready → rendering → done`(점검 통과 또는 주의) / `failed`(`RENDER_FAILED`, 렌더러 없음·글꼴 없음 등). 6장이 모두 `done`이면 단계가 `reviewing`이 돼요.
- 브라우저는 run 하나에서 한 번 띄워 여러 장을 찍고, 취소·서버 종료 때 함께 끝내요(기존 `proc.kill_all`과 같은 방식).

## 가독성 점검 (`checks.layout`)
같은 페이지에서 글자 덩어리마다 재요.
| 항목 | 기준 | 판정 |
|---|---|---|
| 잘림 | 글자 상자가 카드 안전 영역(여백 안쪽)을 넘거나 `scrollHeight > clientHeight` | 넘으면 **실패** |
| 최소 크기 | 본문 32px 이상 (360px 화면에서 약 10.7px) | 밑이면 **실패** |
| 대비 | 글자 상자 아래 배경의 평균 밝기와 글자 색의 대비 4.5:1 이상 | 밑이면 **실패** |
| 겹침 | 글자 상자 아래 배경의 밝기 표준편차(얼룩짐)가 기준 이상이면 물건과 겹친 것으로 봐요 **[AI 기본안: 표준편차 28 이상]** | 넘으면 **주의** |
| 크기 | 저장한 PNG가 1080×1350 | 아니면 **실패** |

- 배경 밝기는 **글자를 숨긴 채 찍은 배경 스크린샷**에서 글자 상자 영역을 잘라 Pillow로 계산해요(새 의존성: `pillow`, `playwright`).
- 결과는 `pass | warn | fail`과 항목별 수치. 어느 덩어리(제목·핵심·본문)가 걸렸는지도 남겨요.

## 자동 고침 (렌더링할 때마다 최대 3번 다시 찍어요)
점검에 걸리면 이 순서로 하나씩 바꿔 다시 찍어요. 사용자가 직접 정한 값은 자동 고침이 덮어쓰지 않아요.
1. **잘림** → 글자 크기를 한 단계 줄여요(제목·핵심만 줄이고 본문은 32px 밑으로 내리지 않아요). 그래도 넘치면 "문구를 줄여 주세요"로 남겨요.
2. **대비 부족·겹침** → 글자 뒤에 옅은 배경(밝은 그림이면 흰색 70% 그라디언트, 어두운 그림이면 검정 55%)을 깔아요.
3. 그래도 대비가 부족하면 → 글자 색을 반대로(검정 ↔ 흰색).
- 무엇을 바꿨는지 `autoFixes`에 남기고 화면에 "자동으로 글자 뒤 배경을 깔았어요"처럼 보여 줘요.

## 직접 조정 (검수 화면)
카드를 누르면 크게 보기 옆에 조정 칸이 열려요.
- 글자 위치: 위 · 가운데 · 아래
- 글자 크기: 작게 · 기본 · 크게 (한 단계 = 8%)
- 글자 뒤 배경: 자동 · 켜기 · 끄기
- 글자 색: 자동 · 어둡게 · 밝게
- 제목·핵심 문장·본문 문구 고치기(글자 수 제한: 제목 30자, 핵심 60자, 본문 160자 **[AI 기본안]**)
- [적용] → `POST /api/projects/{id}/cards/{cardId}/layout` (`layout`, `resultVersion`, `requestId`) → 그 카드만 새 `cardVersion`으로 다시 렌더링(배경 그림은 그대로 재사용, agy 부르지 않음). 다른 카드는 그대로예요.
- 문구를 고치면 스토리보드 원문과 달라진다는 표시를 남겨요(다음 단계의 사실 점검에서 다시 봐요).

## 모바일 미리보기 (검수 화면, S7)
- **전체 보기:** 6장 PNG 격자. 카드마다 점검 결과 배지(통과·주의·실패)와 걸린 항목.
- **하나 보기:** 왼쪽에 원본 크기 축소(1080×1350), 오른쪽에 **가로 360px 휴대폰 틀** 안에 같은 PNG. 점검에 걸린 글자 덩어리는 빨간 테두리로 표시할 수 있게 점검 결과에 상자 좌표를 남겨요.
- 휴대폰 틀은 PNG를 그대로 줄여 보여 줘서, 실제 피드에서 보이는 크기와 같아요.

## 바뀌는 곳
- 새 파일: `cardnews/render/` (HTML 만들기, Playwright 렌더러, 점검·자동 고침), `assets/fonts/`(Pretendard woff2 + OFL), 테스트.
- 고칠 파일: `production.py`(그림 뒤에 렌더링 이어 붙이기), `service.py`(레이아웃 조정 요청), `app.py`(엔드포인트·헬스 체크), `views.js`·`app.js`·`style.css`(검수 화면), `pyproject.toml`, `API_SPEC.md`·`SCREEN_FLOW.md`·`DECISIONS.md`, `README.md`(설치 안내).
- 테스트: 실제 Chromium으로 짧은 렌더 시험(설치돼 있을 때만), 점검·자동 고침 규칙은 가짜 측정값으로, 조정 요청은 그 카드만 버전이 오르는지.

## 검토자 질문에 대한 AI의 결정 (사용자 확인 전)
1. **점검 실패 카드의 상태:** 렌더링이 끝나면 점검 결과와 상관없이 `done`이고, 점검 결과는 `checks.layout.status`(pass·warn·fail)로 따로 보여 줘요. `failed`는 PNG를 못 만든 경우(`RENDER_FAILED`)만이에요. 6장이 모두 `done`이면 `reviewing`으로 넘어가서, 점검 실패 카드를 검수 화면에서 고칠 수 있어요. 화면은 점검 실패 카드를 "완료"가 아니라 빨간 "점검 실패"로 보여 줘요. 다음 단계의 최종 승인은 점검 실패 카드가 있으면 막아요.
2. **렌더링 시점:** 같은 제작 run 안에서 카드마다 그림이 준비되면 바로 이어서 렌더링해요(`generating_image → rendering → done`). `image_retry`도 그림 뒤에 렌더링까지 해요. 직접 조정은 `202 { runId }`를 돌려주는 새 run `render`예요. 그 카드만 다시 렌더링하고, 다른 run처럼 취소·중복 방지(requestId)·진행 중 거절(RUN_IN_PROGRESS)을 따라요. Chromium은 run 하나에서 한 번만 띄워요.
3. **조정 값 저장:** 카드 결과에 `layout`(위치·크기·배경·색·문구)을 두고, 스토리보드는 바꾸지 않아요. 문구를 고친 카드는 `layout.textEdited=true`예요. agy로 다시 만들어도 `layout`은 유지해요. **사용자가 직접 정한 항목은 자동 고침이 건드리지 않아요.** 예를 들어 크기를 "크게"로 정했는데 잘리면, 자동 고침은 다른 항목(배경)만 바꿔 보고 그래도 안 되면 점검 실패로 두고 "크기를 줄이거나 문구를 줄여 주세요"라고 알려요.
4. **SVG 배경 카드:** 같은 방식으로 렌더링하고 같은 점검을 해요. Chromium이 SVG를 그대로 그려요. "AI 생성 이미지" 표기도 똑같이 붙여요.
5. **본문이 없는 예전 스토리보드:** `body`가 없으면 두 덩어리(제목·핵심)만 그려요. 글자 수 제한은 직접 고치는 입력에만 걸어요. AI가 쓴 원문은 길어도 그대로 렌더링하고, 넘치면 잘림 점검이 잡아요.
6. **파일 경로:** 이 문서대로 `results/cards/card_N.v{cardVersion}.png`예요. API_SPEC 2.5의 `pngUrl` 예시를 고쳐요. 렌더용 HTML은 남기되 파일 엔드포인트로는 내주지 않아요(PNG만).
7. **대비 재는 기준:** 글자는 숨기고 **글자 뒤 배경(깔개)은 켠 채** 다시 찍어서 재요. 자동 고침 단계마다 다시 찍어요. 처음 글자 색은 글자 자리 배경의 평균 밝기로 정해요(밝으면 검정 #151515, 어두우면 흰색 #f4f2ee).
8. **`imagePlan.kind`가 none·stock인 카드:** 지금 엔진은 generated만 만들어요. none이면 아이보리 단색 배경에 표기 없이 그리고, stock은 이번 범위 밖이라 none처럼 그려요.
