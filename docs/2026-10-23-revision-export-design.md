# 카드 골라 고치기·최종 승인·내보내기·내보낸 파일 검사 설계

작성: 2026-10-23 · 상태: **검토 중** (승인 전에는 구현하지 않아요)

## 왜 하나
검수 화면에서 "3번 카드의 본문이 길어. 핵심 조건을 유지하며 두 문장으로 줄여 줘"처럼 글로 요청하면, 고른 카드만 고치고 나머지는 손대지 않아야 해요. 다 고친 뒤 최종 승인하면 카드 PNG·ZIP·출처 기록·이미지 사용 기록을 내려받아요. 내보낸 **파일 자체**를 다시 열어 누락·잘림·출처·날짜를 확인하고, 확인하지 못한 것은 "통과"가 아니라 "사용자 확인 필요"로 보여 줘요.

## 이번에 하는 것 / 안 하는 것
- **해요:** 글로 하는 부분 수정(`POST /revisions`), 최종 승인, 내보내기 run, 내려받기 목록·파일, 내보낸 파일 검사 보고서, 화면(S7 수정 요청 칸, S8 내려받기).
- **안 해요:** PDF(선택 기능), 스톡 사진, 이전 버전 되돌리기 화면, 원문 링크가 지금도 열리는지 인터넷으로 다시 확인하기.
- **피해야 할 것:** 고르지 않은 카드의 파일·버전이 바뀌기, 수정 뒤에도 예전 최종 승인이 남기, 확인 못 한 항목을 통과로 표시하기, 승인 안 된 버전을 내려받게 하기.

## 1. 카드 골라 고치기
- 화면(S7): 카드 체크(여러 장) + 수정 지시 입력(500자) + 그림 범위 선택 **[글자만 고치기 / 그림도 다시 만들기 / AI가 판단]** + [선택한 카드만 수정]. 버튼 옆에 "수정하면 최종 승인이 풀려요".
- `POST /api/projects/{id}/revisions` (`cardIds`, `instruction`, `imageScope`: text·image·auto, `version`=result.version, `requestId`) → `202 { runId }`. 단계 `reviewing`·`final_approved`에서 받아요. **받는 즉시 최종 승인을 지워요(`finalApproval=null`), 단계는 `reviewing`.**
- run `revision`:
  1. Claude CLI를 한 번 불러 고른 카드의 새 문구를 받아요. 넘기는 것: 수정 지시, 고른 카드의 현재 제목·핵심·본문·이미지 역할·근거 URL, 그 카드 근거의 조사 기록(사실·한계). 검색 도구는 막고, 조사 세션과 섞지 않게 새 세션·저장 안 함(`--no-session-persistence`). 결과: 카드마다 `title`·`keyLine`·`body`(글자 수 제한 30·60·160), `redrawImage`(bool), `imagePrompt`(그림을 다시 만들 때만), `note`(무엇을 바꿨는지 한 줄).
  2. 지시와 상관없는 카드는 결과에 있어도 버려요. 고른 카드만 반영해요.
  3. 그림 범위: `text`면 그림은 그대로, `image`면 그 카드만 그림을 다시 만들고, `auto`면 엔진의 `redrawImage`를 따라요. 그림을 다시 만들 때는 기존 agy 흐름(실패 시 Claude CLI SVG) 그대로예요.
  4. 고친 문구는 카드의 `layout`(title·keyLine·body)에 넣고 `textEdited=true`. 그 카드만 `cardVersion`이 올라가고 다시 렌더링·점검해요. 고르지 않은 카드는 파일·버전 그대로예요.
- 모의 엔진 프로젝트는 모의 수정기를 써요(본문을 앞 두 문장으로 줄이고, 지시에 "그림"이 있으면 그림을 다시 만들어요).

## 2. 최종 승인
- [최종 승인]은 모든 카드가 `done`이고 **가독성 점검 실패(`fail`) 카드가 없을 때만** 눌려요(주의 `warn`은 승인 가능, 화면에 표시). 서버도 같은 규칙으로 막아요.
- 승인하면 `finalApproval = { resultVersion, approvedAt }`, 단계 `final_approved`, 내보내기 run(`export`)을 시작해요.

## 3. 내보내기 (`exports/v<결과 버전>/`)
- `cards/card_01.png` … : 승인한 버전의 카드 PNG를 순서대로 복사.
- `sources.md`: 조사 기준 시각·기간, 카드별 근거 출처(제목·URL·게시일·공식 여부·엔진이 실제로 열어 봤는지), 카드 문구를 스토리보드와 다르게 고쳤는지.
- `image-credits.md`: 카드별 그림 도구·날짜·프롬프트(agy 대화 ID는 앞 8자리만), 대신 그린 SVG면 그 사실, "AI 생성 이미지" 표기 여부. 생성 이미지를 "저작권 없음"으로 부르지 않아요.
- `cardnews_<projectId>_v<버전>.zip`: 위 파일 전부.
- `verify.json` + `verify.md`: 아래 검사 결과.
- 내려받기: `GET /api/projects/{id}/exports` → 최종 승인된 버전의 파일 목록(검사 통과한 파일만), `GET /api/projects/{id}/exports/v<버전>/<파일>` → 내려받기(`Content-Disposition: attachment`). 승인 전·수정 중이면 `STAGE_CONFLICT`.

## 4. 내보낸 파일 검사 (ZIP을 다시 열어서)
결과마다 **통과 / 실패 / 사용자 확인 필요** 셋 중 하나예요. 확인 못 한 것은 통과가 아니에요.

| 항목 | 확인 방법 | 통과 | 실패 | 사용자 확인 필요 |
|---|---|---|---|---|
| 누락 | ZIP 목록에 스토리보드 카드 수만큼 PNG + sources.md + image-credits.md가 있는지, 각 PNG를 열 수 있는지 | 다 있음 | 빠진 파일·못 여는 파일 | — |
| 크기 | ZIP 안 PNG를 열어 1080×1350인지 | 맞음 | 다름 | — |
| 글자 잘림 | 렌더링 때 잰 넘침 값(PNG만으로는 잘림을 알 수 없어요) + ZIP 안 PNG가 그 렌더링 파일과 같은지(SHA-256) | 넘침 없음 + 같은 파일 | 넘침 있음 | 같은 파일인지 확인 못 함 |
| 출처 | 카드마다 근거 URL이 있는지, 조사 후보·기록에 있는 URL인지, sources.md에 적혔는지, 엔진이 실제로 열어 봤는지(D12) | 근거 있음 + 열어 봄 | 근거가 조사에 없는 URL | 근거 없음(표지·요약 포함) / 열어 보지 않은 출처 / 링크가 지금도 열리는지(확인 안 함) |
| 날짜 | 근거 후보의 게시일이 조사 기간 안인지, 카드 문구에 나온 날짜(YYYY년 M월 D일, M월 D일 등)가 조사 기록·후보 날짜에 있는지, '최신'을 썼다면 기준일·게시일이 있는지 | 기간 안 + 문구 날짜가 기록에 있음 | 기간 밖 | 게시일 미확인 / 문구 날짜를 기록에서 못 찾음 |

- 결과는 내려받기 화면 위쪽에 요약(통과 n · 실패 n · 확인 필요 n)과 카드별 표로 보여 주고, "확인 필요" 항목은 **무엇을 어디서 보면 되는지** 한 줄로 적어요.
- 실패가 있으면 그 파일은 목록에서 빼지 않고 빨간 표시로 보여 줘요(내려받아 볼 수는 있게). [다시 수정하기]로 돌아가면 승인이 풀려요.

## 바뀌는 곳
- 새 파일: `cardnews/revise.py`(Claude CLI·모의 수정기), `cardnews/export.py`(파일 만들기·ZIP), `cardnews/verify_export.py`(검사), 테스트.
- 고칠 파일: `production.py`(revision run: 문구 반영 + 필요한 카드만 그림·렌더링), `service.py`(revisions·최종 승인 규칙·내보내기 목록), `app.py`(엔드포인트·파일 내려받기), `worker.py`(export run), `pipeline.py`, `views.py`(exportsReady), `static/*`(S7 수정 칸·최종 승인, S8), `tests/fake_claude.py`(수정 결과), 문서(API_SPEC·SCREEN_FLOW·DECISIONS D19·README).
